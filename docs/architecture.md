# 架构：组件边界与数据流

## 进程树（用户视角）

```
EniLauncher.exe                    ← 用户双击的唯一入口（托盘 + 独立窗口）
└── node eni-launcher.js           ← 客户端 HTTP 服务（127.0.0.1:8444）
    └── node eni-proxy.js          ← 协议代理（127.0.0.1:8443，父子进程绑定）
        └── 外部 AI 客户端（ZCode/DSH/Codex/...）的请求打到 8443

node eni-guard.js                  ← 开机自启；只做配置自愈，不碰代理生命周期
```

## 生命周期规则

| 事件 | 行为 |
|---|---|
| 托盘宿主启动 | 拉起 launcher → launcher 拉起 proxy → 打开独立窗口 |
| 窗口关闭（托盘还在） | 收进托盘，proxy 继续跑（功能保持） |
| 托盘「退出」 | 通知 launcher 自杀 → launcher 杀 proxy → 全链路停止 |
| launcher 异常死亡 | proxy 检测父进程消失，8 秒内自杀 |
| proxy 掉线 | launcher 心跳周期（60s）内重拉 |
| 客户端重装/配置重置 | guard 60 秒内还原注入（用户点过「还原」的平台除外） |

## 三层强校验（不激活进不了主界面）

```
GET /  →
  ① 有本地 token？
     否 → 登录/注册页
  ② 服务端校验该账号授权状态（Ed25519 验签）
     session-invalid → 清 token 回登录页
     未激活 → 卡密激活页（服务端判定，页面只是渲染）
     已激活 → 主界面 HTML + 全部状态数据（只有这一层才下发）
```

主界面数据（卡号、到期、平台状态、代理状态）**只对已激活账号下发**；未激活时接口只返回最小信息。

## 通信信任链

```
客户端 ──HTTPS──▶ 授权服务端
   ◀── 响应 + sig（Ed25519 签名，覆盖"去 sig 后 sorted-keys compact JSON"）

客户端校验：
  ① Host/DNS：域名解析与首次锁定一致（IP 变了由签名裁决）
  ② 公钥：首次固化 pubkey.pin，变了 = 拒绝
  ③ 签名：Ed25519 验签（canon JSON 与服务端逐字节对齐）
  ④ 新鲜度：到期时间按凭据单调（防重放旧 active 响应）
```

## 数据落盘

| 文件 | 内容 | 敏感度 |
|---|---|---|
| `etc/account.json` | 登录 token + 绑定卡号 + 机器码 | 本地明文（仅本机回环服务可读） |
| `etc/pubkey.pin` | 服务端签名公钥（首次锁定） | 公开无害 |
| `etc/server.pin` | 域名解析 + 证书指纹记录 | 公开无害 |
| `etc/manifest.sha256` | bin/*.js 完整性清单（启动自校验） | — |
| `etc/disabled/<id>` | 用户点过「还原」的平台标记 | — |
| `<平台配置>.eni-orig` | 注入前的原始配置备份 | 仅在原始态生成 |
