## 这是什么

一套给桌面 AI 客户端（ZCode / DSH / Codex / WorkBuddy / Hermes）做**统一能力增强**的本地框架：

- **一个客户端界面**：登录账号 → 卡密激活 → 主界面（状态面板 / 平台管理 / 服务控制）
- **一个本地代理**：所有接入的客户端请求经过本地协议层，完成模型路由、上下文注入、用量治理
- **一份配置管理**：五个平台的接入/还原，一个按钮搞定，原始配置自动备份
- **一套生命周期**：客户端在跑 = 功能在；客户端退出 = 功能立即失效；后台守护只做配置自愈

## 架构

```
┌─────────────────────────────────────────────────────────┐
│                    EniLauncher.exe（托盘宿主）              │
│   登录/注册 → 卡密激活 → 主界面（平台卡片 · 激活/还原）      │
│   独立窗口 · 系统托盘常驻 · 退出即停止功能                    │
└──────────────┬──────────────────────────────────────────┘
               │ spawn（父子进程绑定：托盘退出 → 代理自杀）
┌──────────────▼──────────────────────────────────────────┐
│                 eni-proxy（本地协议代理 127.0.0.1:8443）     │
│   请求改写 · 模型路由 · 上下文注入 · 卡密闸门 · 流式透传      │
└──────┬────────┬────────┬────────┬────────┬──────────────┘
       ▼        ▼        ▼        ▼        ▼
    ZCode     DSH     Codex   WorkBuddy  Hermes
    (baseUrl → 127.0.0.1:8443 / 人格文件注入)
```

## 核心设计（为什么这么拆）

1. **客户端在跑才有效果**：代理进程由托盘宿主拉起、父子进程绑定。关掉客户端 = 代理自杀 = 全部平台直连原始服务。后台守护**故意不管代理生命周期**，否则"关了软件功能还活着"。
2. **不激活进不了主界面**：主界面的 HTML 只对"已激活账号"下发，前端改 JS 也拿不到——校验在服务端，不在页面。
3. **一号一机（会话单点）**：卡密绑账号不绑机器。新设备登录同账号，旧设备会话立刻失效并自动下线，换机不需要换绑。
4. **信任链在签名**：服务端响应全部带 Ed25519 签名；客户端公钥锁定（首次固化），假服务器 / DNS 劫持 / 重放旧响应都过不了。域名换了 IP 时由签名裁决：签名对 = 真服务器换 IP，签名错 = 拒绝通信。
5. **防篡改**：安装时生成 SHA-256 清单，客户端启动自校验，文件被改一个字节就拒绝运行；同时检测常见调试/抓包工具。
6. **还原尊重用户**：点过「还原」的平台，守护进程不再自动改回（disabled 标记）；只有原始（未注入）状态才允许生成备份，脏备份不能用于还原。
